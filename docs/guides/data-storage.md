# 데이터는 어디에 두나

플러그인이 값을 남길 곳은 다섯 군데이고, **무엇을 남기느냐**로 고릅니다. 헷갈리면 이 표의 위에서부터 맞는 첫 줄을 씁니다.

| 남기는 것 | 둘 곳 | 쓰는 법 | 사라지는 때 |
|---|---|---|---|
| 사용자가 넣는 설정 · 비밀(주소 · 계정 · 비밀번호) | **설정 칸** (`plugin.json` 의 `settings`, 비밀은 `type: "secret"`) | `host.settings()` · 서버는 `${storage:키}` · `${secret:키}` 를 `env` 로 받음 | 플러그인을 지울 때 |
| 작은 상태 몇 개(기본값 · 화면 상태, 64KB 이하) | **`storage`** | 서비스 `host.call('storage.get' \| 'storage.set')`, 패널은 `service.call` 로 맡김 | 플러그인을 지울 때 |
| 플러그인이 **만들어 쌓는 기록 · 색인 · 상태**(수행 이력 · 목록 · 등록부, 다시 만들 수 있는 것) | **`host.db`** (문서 저장소) | 서비스 `host.db.*`, MCP 서버 프로세스는 `sdk/litecode-db-client.mjs` | 플러그인을 지울 때(업데이트 · 재설치로는 안 지워짐) |
| 사람이나 AI 가 읽고 고치는 **원본 · 산출물**(시나리오 · 규칙 문서 · 결과서 HTML) | **프로젝트 파일** | 서버가 파일로 쓴다(아래 "프로젝트 파일 규칙") | 안 지워짐(프로젝트 것) |
| 크고 프로젝트에 남길 이유가 없는 것(스크린샷 · 캐시 · 내려받은 것) | **앱 데이터 폴더**(`dataDir`) | 서버 env `${dataDir}` | 플러그인을 지울 때 |

## 가르는 기준 세 가지
1. **다시 만들 수 있나?** 없으면 DB 가 아니라 파일에 둡니다. `host.db` 는 깨지면 앱이 옆으로 치우고 빈 채로 시작합니다. 시나리오 같은 원본은 파일이 정본이고, DB 에는 그 파일을 찾고 훑기 위한 색인만 둡니다.
2. **사람이 직접 열고 고치나?** 그렇다면 파일입니다(`.md` · `.html`). DB 문서는 사람이 열 수 없습니다.
3. **프로젝트 폴더에 남아도 되나?** 크기가 크거나 이 PC 에서만 의미가 있으면(스크린샷 · 캐시) 앱 데이터 폴더입니다. 프로젝트에 쓴 파일은 git 에 올라갈 수 있습니다.

## DB 와 파일을 잇는 법 — id 로 찾는다
**DB 문서에 파일 경로를 적지 않습니다.** 파일 이름 · 폴더 이름이 곧 DB 문서의 id 가 되게 짓고, 경로는 id 에서 계산합니다. 경로를 적어 두면 파일을 옮기거나 프로젝트 폴더가 바뀔 때 어긋납니다. 파일이 바뀐 것은 문서에 지문(fingerprint)을 두어 알아채고, DB 가 비면 파일 이름만으로 다시 채웁니다(reindex). 파일이 사용자에 의해 지워졌으면 그 DB 줄도 지웁니다.

## DB 를 쓸 때
- **누가 쓰나:** 서비스는 `host.db`, MCP 서버 프로세스는 `sdk/litecode-db-client.mjs`(서버 번들 옆에 **복사해서** 쓴다 — 서비스 번들과 한 파일로 묶지 않는다). 패널은 못 쓰고 `service.call` 로 서비스에 맡깁니다. 환경변수가 없으면(`createDbClient()` 가 `undefined`) 앱 밖 실행 · CI · 옛 앱이니 대체 길이 필요한지 정합니다.
- **id 는 시각으로 시작**하게 짓습니다(`2026-11-10T09-00-00_<번호>`). id 순 `list` 가 곧 시간순이 되어 정렬 · 조건 `query`(컬렉션을 훑고 앱을 멈춘다)를 피합니다.
- **한도:** 문서 256KB · 컬렉션 20개 · 컬렉션당 문서 5만 개 · 플러그인 총 200MB. 이력은 개수를 정해 넘치면 오래된 것부터 지웁니다.
- 서비스 쪽 자세한 사용법은 [서비스 가이드 3-1](service-plugin.md#3-1-문서-저장소--hostdb)입니다.
- 호스트 API 2 를 선언해야 하므로(`service.api: 2`) 옛 앱(api 1)에는 설치되지 않습니다.

## 프로젝트 파일 규칙
- **사용자가 시키지 않았는데 프로젝트 폴더 바깥을 쓰지 않습니다.** 쓰는 폴더는 사용자가 이미 알고 있는 이름으로 하나만 둡니다(아래 현황).
- 앱의 `project.writeFile` 은 `.litecode/` 바로 아래 `.md` 한 단계만 쓸 수 있습니다. 그 밖의 파일(결과서 폴더 · 코드)은 파일 권한이 있는 MCP 서버 프로세스가 `cwd`(프로젝트 폴더) 기준으로 씁니다. 서버는 **실제 경로(심볼릭 링크를 푼 것)가 프로젝트 안인지** 확인하고 쓰고, 지우는 것도 우리가 만든 폴더 이름 모양일 때만 합니다.
- 지금은 플러그인을 지워도 프로젝트에 쓴 파일이 남습니다(DB · 앱 데이터 폴더는 같이 지워짐). 지울 때 프로젝트 폴더도 함께 지우는 기능은 desktop 에 요청 중입니다.
- 지울 때는 그 파일과 짝인 DB 줄 · 앱 데이터 폴더의 스크린샷을 함께 지웁니다.

## 지금 플러그인들은 어디에 두나
| 플러그인 | 설정 · 비밀 | `storage` | `host.db` | 프로젝트 파일 | 앱 데이터 폴더 |
|---|---|---|---|---|---|
| ui-test (0.6) | 대상 주소 · 계정 · 비밀번호 · 테스트 폴더 | 패널 기본값(`prefs`) | (0.7 에서 시나리오 목록 · 수행 기록) | `ui-tests/` — 시나리오 md · 생성 코드 · `_reports/` 결과서 | 수행 이력 JSON · `shots/` 스크린샷 |
| sql-tuning | DB 연결 정보 · 비밀번호 | — | — | `sql-tuning-reports/<시각>/` 결과서 · `.litecode/sql-standard.md` 표준 | — |
| token-pet | — | 빛톨 상태(`state`) | (필요해지면 도감 · 이름) | — | — |
- **기존 위치는 바꾸지 않습니다.** 새 플러그인만 이 표의 기준을 따릅니다.

## 새 플러그인을 만들 때
1. 남길 것을 위 표에 하나씩 대 보고 둘 곳을 정합니다. 둘 곳이 둘로 갈리면(원본은 파일, 목록은 DB) 한쪽이 정본임을 `README.md` 의 `## 구성` 에 적습니다.
2. 프로젝트에 쓰는 폴더가 있으면 `README.md` 에 이름 · 안에 무엇이 들어가는지 · 지울 때 어떻게 되는지를 적습니다.
3. 비밀은 설정 칸의 `secret` 으로만 받고 파일 · DB · `storage` 에 쓰지 않습니다.
